# Codex adapter

Codex reads `AGENTS.md` natively, so the entrypoint needs no bridge. What it
does not share with the neutral core is an MCP configuration format. This
directory holds the manifest and the configuration head that close that gap.
The file they produce is generated by `scripts/sync-harness.py` and tracked
in git, so a clone needs no step between clone and session. Skills and roles
reach a session through installed packs, and the wiki pack carries a
`.codex-plugin/plugin.json` for this harness.

## Getting started on this harness

1. Clone the workbench and run the wiring check from its root:

   ```bash
   python3 scripts/check-harness.py
   ```

   `0 failure(s)` means every generated file matches its source. On Windows, clone with
   `git clone -c core.symlinks=true` first, and never use a zip download,
   which flattens a symlink into a text file.

2. Install the wiki pack, then the packs chosen in `prompts/setup.md` stage
   0. Register this repo as a marketplace in `~/.codex/config.toml`, with the
   remote URL or the local path as its `source`, then run `/plugins` in a
   session and install `wiki` from it. The pack's manifest for this harness
   is `wiki/.codex-plugin/plugin.json`, which names the skills directory.
   Every other pack comes from its own marketplace, registered the same way;
   `README.md` at the root lists one working set under "Packs and plugins".
   A pack that ships roles for this harness carries them as TOML files and
   its own install step, because this harness has no dependency concept and
   reads roles only from `~/.codex/agents/` or `.codex/agents/`.

3. Start a session at the workbench root and trust the project:

   ```bash
   codex
   ```

   "Codex loads project-scoped config files only when you trust the project"
   (`https://learn.chatgpt.com/docs/config-file/config-reference`, retrieved
   2026-09-12). Trust is recorded as `projects.<path>.trust_level = "trusted"`
   in the user-level configuration (same page and date). How the harness asks
   for it is not on that page; if no prompt appears, write the key by hand.
   Until the project is trusted, `.codex/config.toml` and `.codex/agents/`
   are not read.

4. Confirm the surfaces loaded. `/skills` lists the five wiki skills and each
   chosen pack's, or type `$` to mention one ("In Codex CLI or the IDE extension, run `/skills` or type
   `$` to mention a skill", `https://learn.chatgpt.com/docs/build-skills`,
   retrieved 2026-09-12). The documentation retrieved on 2026-09-12 names no
   command that lists custom agents; a dispatch that names one by its `name`
   is the test.

5. Paste `prompts/setup.md` into the session. It walks the specialisation
   pass and ends by running the checks above again.

## What this adapter declares

`wiring.json` beside this file declares no symlink and one generated
configuration file. A second path is this harness's and not in the manifest,
because it is a pack manifest and not wiring: `wiki/.codex-plugin/plugin.json`.

| Path | What it is | Source | Retrieved |
|---|---|---|---|
| `.codex/config.toml` | Generated: the head in `config.toml` beside this file, then one `[mcp_servers.<name>]` table per server in `.mcp.json`. Project-scoped configuration lives at `.codex/config.toml (trusted projects only)` | `https://learn.chatgpt.com/docs/extend/mcp` | 2026-09-12 |
| `wiki/.codex-plugin/plugin.json` | The wiki pack's manifest for this harness: `name`, `version`, `description`, and `skills` pointing at `./skills/`. Skills are scanned from `$REPO_ROOT/.agents/skills` and from installed plugins | `https://learn.chatgpt.com/docs/build-skills` | 2026-09-12 |

Roles are not generated here. A pack that ships roles for this harness
carries them as standalone TOML files, "with each file defining one custom
agent", where "every standalone custom agent file must define: `name`,
`description`, `developer_instructions`"
(`https://learn.chatgpt.com/docs/agent-configuration/subagents`, retrieved
2026-09-12), and installs them into `~/.codex/agents/` by its own step.

After any edit to `.mcp.json` or to the head:

```bash
python3 scripts/sync-harness.py
```

`scripts/check-harness.py` fails until the generated file matches.

### How the MCP block is generated

`.mcp.json` at the workbench root is the one source of MCP servers. The
generator renders two shapes into `[mcp_servers.<name>]` tables and refuses
everything else by name, because a server the two harnesses read differently
is a server that works on one and silently not the other:

- A local server: `command`, `args`, and `env` become `command`, `args`, and
  `[mcp_servers.<name>.env]`. A value containing `${` is refused, because the
  target format performs no expansion.
- A remote server: `type: "http"` or `"sse"` with `url` becomes `url`. A
  header of exactly `Authorization: "Bearer ${NAME}"` becomes
  `bearer_token_env_var = "NAME"`. Any other header is refused.

The documented shapes are `command`, `args`, `env` for a local server and
`url` with `bearer_token_env_var` for a remote one
(`https://learn.chatgpt.com/docs/extend/mcp`, retrieved 2026-09-12).

`config.toml` beside this file is the hand-edited head of the generated file.
Edit it, never `.codex/config.toml`. It ships as comments only.

## Keys a project-scoped configuration cannot set

"Project-scoped config can't override machine-local provider, auth, host-owned
app request metadata, notification, configuration profile selection, or
telemetry routing keys." The ignored keys include `openai_base_url`,
`model_provider`, `model_providers`, `notify`, `profile` and `profiles`
(`https://learn.chatgpt.com/docs/config-file/config-reference`, retrieved
2026-09-12). A self-hosted run that changes only `.codex/config.toml` therefore
changes nothing; those keys belong in `~/.codex/config.toml`.

`agents.enabled` defaults to `true` (same page), so custom agents need no
feature flag of their own.

## Permissions

The template ships no permission rules. A custom agent inherits the session's
sandbox unless its file sets `sandbox_mode`, which is the pack's choice
("Subagents inherit your current sandbox policy",
`https://learn.chatgpt.com/docs/agent-configuration/subagents`, retrieved
2026-09-11).

## The entrypoint and the size cap

Codex reads `AGENTS.override.md` if it exists, otherwise `AGENTS.md`, from the
project root down to the working directory, and "skips empty files and stops
adding files once the combined size reaches the limit defined by
`project_doc_max_bytes` (32 KiB by default)"
(`https://learn.chatgpt.com/docs/agent-configuration/agents-md`, retrieved
2026-09-12). `scripts/check-harness.py` fails when the root `AGENTS.md` alone
exceeds that cap.

## The page schema arrives by reference

Same as every adapter: the routing row in `AGENTS.md` names
`central-context/AGENTS.md`, and each wiki skill names it as a required read.
Nothing in this adapter imports it. Schema column: `reference`.

## Model

Whatever `~/.codex/config.toml` selects. A role's model is pinned in the pack
that ships it, and checked only by the harness.

## Removing the adapter

```bash
git rm -r .codex adapters/codex wiki/.codex-plugin
```

`scripts/check-harness.py` then has no manifest for this harness and checks
nothing for it. `scripts/sync-harness.py --check` reports nothing to generate.
